# Architecture Constraints

This page explains the architectural constraints and restrictions with further details.

## Technical

| Constraint                     | Description                                                                                                                                                                                                                                                                                                                                 |
|--------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Platform-indepentent**       | Innamark aims to work on various operating systems (Windows, Linux, macOS) and within existing IT landscapes and programming languages. Therefore, the core watermarking library is created using [Kotlin Multiplatform](https://kotlinlang.org/multiplatform/) to be used within backend (Java, Kotlin) and frontend (JavaScript) systems. |
| **Mono-repository**            | The public [Innamark GitHub repository](https://github.com/FraunhoferISST/Innamark) uses a [monolithic repository approach](https://en.wikipedia.org/wiki/Monorepo) and consists of different parts, located in different subfolders.                                                                                                       |                                                                                                                                                                                                                                                                                                                                             |
| **Build Tool**                 | Gradle is used as a main build tool for the different components.                                                                                                                                                                                                                                                                           |
| **Development Tools**          | Most of the team use [IntelliJ IDEA](https://www.jetbrains.com/idea/) for development and run the project using [Docker](https://www.docker.com/).                                                                                                                                                                                          |
| **Release & Versioning**       | Only the source code is published. We do not publish pre-build binaries or containers and do not have a consistent release process.                                                                                                                                                                                                         |
| **Production-readyness & TRL** | The project is still in heavy development with breaking changes. It should be seen as a working prototype, so use at your own risk.                                                                                                                                                                                                         |

## Organizational

| Constraint                 | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|----------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Team**                   | Innamark was initially started by Malte Hellmeier and his research and development team at the [Fraunhofer ISST](https://www.isst.fraunhofer.de/en.html).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Schedule**               | The first idea started in 2022, with a patent application in 2023, and the GitHub publication in 2024.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Organization & Funding** | Innamark is developed by the applied German research institute [Fraunhofer ISST](https://www.isst.fraunhofer.de/en.html). The initial project version was created within the scope of the [Center of Excellence Logistics and It](https://ce-logit.com/), also supported by the [Fraunhofer Cluster of Excellence Cognitive Internet Technologies CCIT](https://www.cit.fraunhofer.de/en.html) and [AHEAD as Fraunhofer's Deeptech Incubator](https://www.ahead.fraunhofer.de/en.html).                                                                                                                                                                                                                                                                                                                                                                                                           |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Licensing (Patent)**     | The core watermarking concept is protected by a pending [German](https://patents.google.com/patent/DE102023125012A1) and [international](https://patents.google.com/patent/WO2025056772A1/en) patent application. The source code of different components (watermarking library, webinterface, CLI tool) is [published on GitHub](https://github.com/FraunhoferISST/Innamark) under the Fraunhofer License which is based on the MIT license and respects the patent protection. In order to use the Innamark watermarker, a patent license is required in addition to the license of the software. See [LICENSE](https://github.com/FraunhoferISST/Innamark/blob/main/LICENSE) for more information. Consequently, new contributions are welcome and need to follow and accept our [Corporate Contributor License Agreement (CLA)](https://github.com/FraunhoferISST/Innamark/blob/main/CLA.md). |
| **Publications**           | Since Innamark was developed at a research institute, different publications in peer-reviewed conferences and journals arose over time (see [Hellmeier et al. (2025)](https://doi.org/10.24251/HICSS.2025.886), [Hellmeier et al. (2025)](https://doi.org/10.1109/ACCESS.2025.3583591), [Hellmeier (2026)](https://doi.org/10.5220/0014268700004061)).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

## Conventions

| Constraint            | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
|-----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Documentation**     | The documentation is [published on GitHub](https://fraunhoferisst.github.io/Innamark/) while the architecture part is structured based on [arc42](https://arc42.org/) with mostly [PlantUML](https://plantuml.com/) diagrams.                                                                                                                                                                                                                                        |
| **Coding Guidelines** | We follow various guidelines, like using [conventional commits](https://github.com/conventional-changelog/commitlint), consistent license headers and documentation, and code style based on the [Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html) and the [KDoc syntax](https://kotlinlang.org/docs/kotlin-doc.html). See [CONTRIBUTING](https://github.com/FraunhoferISST/Innamark/blob/main/CONTRIBUTING.md) for more information. |
| **GitHub**            | In GitHub, we fork on feature branches that are merged into `main` via reviewed pull requests. Every pull request title follows the [conventional commit schema](https://github.com/conventional-changelog/commitlint) because we use *squash and merge*.                                                                                                                                                                                                            |
